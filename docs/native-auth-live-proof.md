# Integrated native-auth TLS/browser proof

## Result

PASS on the recorded snapshot — `node --import tsx scripts/ui-native-auth-live.mjs` completed with **exit 0**, including resource cleanup, on Node **26.10.0** and an independently installed Node **22.19.0** source copy (macOS arm64). Each run exercised six integrated journeys against the actual controller, private SQLite auth state and Better Auth implementation. No HTTP responses were mocked. Overall acceptance and subsequent-code reruns are tracked separately in the [verification record](native-auth-verification.md).

Reproduce from repository root:

```sh
npm run build:web
BROWSER_TOOLS_DIR=/path/to/browser-tools \
  node --import tsx scripts/ui-native-auth-live.mjs
```

Requires existing `puppeteer-core` in that browser-tools installation, Chrome (override with `CHROME_PATH`), Node/tsx and OpenSSL. No new dependency was installed.

## Observed assertions

1. French login renders at 390px without horizontal document overflow; language switches to English. Before access, the actual UI makes no protected API requests and constructs no EventSource. Real password login enters restricted enrollment; `/api/health` returns 403. UI submits the setup key and password, displays the real seed, and verifies an OTP generated by Better Auth's OTP utility. Enrollment verification still does not mount App or open feeds; health remains 403.
2. Explicit UI signout followed by password login and a genuinely new TOTP time step reaches the full App and health 200. No clock or replay reservation is altered. Browser cookies are Secure, HttpOnly, SameSite=Lax, host-only and path `/`; raw Set-Cookie headers have no Domain attribute. `document.cookie` is empty. Auth JSON is inspected for session-token fields and no-store caching.
3. The actual Agents “Set as default” button sends a POST with **no body** and `Content-Type: application/json`; the real backend returns 200 and the catalog records the selected agent.
4. Settings replaces recovery codes with password confirmation and explicit acknowledgment. New material appears in the UI and disappears when dismissed. A separate isolated browser context successfully logs in using a replacement code.
5. A third context cannot replay that consumed code (401), cannot mount the App, and gets health 401. After a fresh password challenge, an old enrollment recovery code also returns 401 following replacement.
6. A sibling tab shares the first context's session and opens a real global SSE feed. UI logout revokes that context only. The sibling's stream closes at the real heartbeat/revalidation boundary, the UI returns to login and EventSources close. The second context still gets health 200. After its UI logout, global SSE listener count is zero.

The fixture checks that password, setup key, replacement recovery codes and cookie values are absent from browser persistent storage. It produces no screenshots, traces, cookie dumps, seeds or recovery material in its report.

## Isolation and cleanup

- Fresh mode-0700 temporary home, fake owner/password, real `lockHome` and initialization APIs. Synthetic catalog agent is created through the domain API solely to exercise the no-body mutation.
- Every configured catalog/provider/agent/skill path is beneath the disposable home. No real account/settings are loaded; no CLI initialization, SSH or deployment is invoked.
- Disposable self-signed TLS certificate and Node HTTPS proxy on a random loopback port; actual backend on another random loopback port. Browser Host and Origin pass through unchanged to the configured HTTPS origin.
- Headless Chrome uses a new temporary user-data directory and isolated contexts, never a user's profile. Only this browser accepts the disposable certificate.
- Pool factory throws on any provider spawn; observed spawn count is zero.
- **Zero rate-counter resets.** The fixture explicitly waits 11 seconds between factor journeys for the real shared rate window. It does not prove rate-limit enforcement under load.
- `finally` closes the owned browser, proxy requests/sockets, both servers, both databases and data-home lock, then removes the temporary home. PASS is emitted only after cleanup. Timeouts/assertion errors produce a nonzero exit.
- Earlier fixture runs failed at background-tab DOM waits: Puppeteer's default animation-frame polling can stall in background tabs. Explicit 100ms polling removed that harness issue. Those failed runs were not counted as passes; no product change was made.

## Explicitly unproven here

This is a functional DOM/network integration regression, not visual screenshot review. Provider work continuation cannot be exercised with the forbidden-spawn factory. Per-conversation SSE requires provider spawning and is not exercised; the real global feed is covered. Full hostile HTTP/rate-limit/concurrency matrices, offline recovery/crash faults, private IPC, expiry deadlines, lost-response recovery, network-failure UX, other runtime/platform combinations, performance/capacity, VPS isolation/deployment and full Plan 0002/P0–P5 acceptance remain separate gates. No deployment, commit or push was performed.
