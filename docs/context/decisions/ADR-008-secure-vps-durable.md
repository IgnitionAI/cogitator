# ADR-008 — Authenticated personal VPS access and a separate durable runtime

Status: proposed for implementation; original requirements/design reviewed on 2026-10-09. The external-identity/Firetower access choice is superseded by [ADR-009](ADR-009-native-owner-auth.md) and Plan 0003 following owner confirmation on 2026-10-10. Durable/isolation requirements remain proposed. ADR-009's local authentication/IPC/store clarifications are now reviewed and adopted; production Durable contract amendments are not.

Cogitator will support one authenticated owner over public HTTPS and new remote missions that recover from process interruptions. The revised direction uses native product-owned owner authentication (Plan 0003), isolated execution, and a single Pi Durable harness owning persistent runtime state. Existing local RPC sessions and their pi JSONL transcripts remain intact; they are not silently converted or used as a remote execution fallback.

Supervising the current RPC processes alone does not satisfy checkpoint recovery. Replacing the entire runtime at once would unnecessarily risk existing integrations and histories, while Pi Durable remains experimental. Authentication, durable execution, and operating-system isolation are separate boundaries; none substitutes for the others. Durable submission deduplication does not provide exactly-once external effects.

Historically, before the native-auth pivot, the owner selected the existing Firetower VPS and approved access preparation using its existing Caddy service, a dedicated sslip.io hostname, and a separate self-hosted Authelia OIDC provider with required MFA. This adds explicit identity-service enrollment, recovery, SMTP and protected-backup responsibilities. It does not remove oauth2-proxy/backend token validation or authorize exposing the current classic runtime. Initial setup may serve only the identity portal and an application-host maintenance response, with privileged changes confirmed by the operator. P1–P5 proof is still outstanding. Subsequent inspection found an existing Authelia service path for AionUI; a read-only admin inventory was proposed before deciding between a new OIDC client and a separate instance. That handoff and all further Firetower changes are now suspended. Do not replace or weaken the existing AionUI access boundary.

A future reviewed Durable implementation must still explicitly scope I3/I5, O6 and ADR-006 for that new runtime. ADR-009's adopted O4/O7/auth-store clarifications do not authorize Durable transcripts in the catalog or unrestricted remote execution. Retain loopback TCP binding and keep remote agents from bypassing approval or secret boundaries through local tools, MCP or shell execution. See [Plan 0002](../plans/active/0002-secure-vps-durable.md) for defaults, alternatives, decision log, review disposition and release gates. This ADR does not authorize infrastructure changes, spending, or production deployment.
